# Nova — архитектура категорий

Документ описывает слой `apps/web/src/categories/`. Остальные модули
(`features/`) не менялись, дизайн-система тоже: новые экраны используют
существующие токены и классы.

## Главный принцип

Категория — это **данные, а не код**. Конфигурация описывает, что за категория,
какие в ней типы объектов и какие у них поля. Роутинг, список, фильтры,
карточка и форма публикации строятся из этой конфигурации автоматически.

Следствие: добавление категории не требует правок в общих файлах. Ошибка в
одной категории не может сломать другую, потому что они не пересекаются в коде.

## Одно поле — три экрана

Ключевое решение. Каждое поле описывается один раз и само говорит, где оно
показывается:

```ts
{
  key: 'mileage',
  label: 'Пробег',
  type: 'number',
  unit: 'км',
  required: true,
  step: 3,              // шаг мастера публикации
  filterable: true,     // попадает в фильтры
  filterKind: 'range',  // фильтруется диапазоном «от–до»
  showInCard: true,     // выводится строкой в карточке
}
```

Форма, фильтры и карточка физически не могут разойтись — они читают один
источник. В исходных макетах это расходилось: продавец авто заполнял привод и
цвет, а фильтровать по ним было нельзя; карточка вакансии была беднее формы,
которая её создавала.

## Три уровня изоляции

**1. Валидация при регистрации** (`core/validate.ts`)

Битая подкатегория отбрасывается **по одной**, категория живёт с остальными.
Категория без единой рабочей подкатегории не поднимается, приложение работает.
Что отбрасывается: подкатегория без шагов или полей, поле без ключа или с
неизвестным типом, `select` без вариантов, дублирующийся ключ поля, поле с
номером шага за пределами мастера.

**2. Перехват при регистрации** (`core/registry.ts`)

`registerCategory` обёрнут в try/catch. Модуль, упавший прямо в момент
подключения, попадает в список `failed`, следующие подключаются нормально.

**3. Предохранители в интерфейсе** (`core/CategoryBoundary.tsx`)

Стоят на двух уровнях: вокруг категории и вокруг каждой подкатегории. Сбой в
«Земельных участках» гасит один экран — остальная «Недвижимость» и другие
категории работают.

Диагностика: `getRegistryHealth()` возвращает три списка — `ok`, `degraded`
(с перечнем отключённых подкатегорий), `failed` (с причинами). В режиме
разработки печатается в консоль при старте.

## Структура

```text
apps/web/src/categories/
├── core/
│   ├── types.ts             контракты: CategoryModule, Subcategory, FieldDef
│   ├── validate.ts          проверка конфигурации, отбрасывание битого
│   ├── registry.ts          реестр, перехват сбоев, health
│   ├── CategoryBoundary.tsx предохранитель (категория / подкатегория)
│   ├── CategoryRoutes.tsx   один роутер на все категории
│   ├── homeGrid.ts          сетка главного экрана — один источник правды
│   ├── filtering.ts         фильтрация, сортировка, форматирование
│   ├── draftStore.ts        черновики форм
│   ├── RegionStore.tsx      регион как сквозной параметр
│   ├── AuthGate.tsx         точки входа: публикация, связь, отклик
│   ├── catalogData.ts       демоданные (заменяются API)
│   └── isolation.test.ts    тесты автономности
├── ui/                      типовые экраны, общие для всех категорий
│   ├── CategoryHomePage.tsx «Что вы хотите сделать?»
│   ├── SubcategoryPicker.tsx выбор типа объекта с поиском
│   ├── ListPage.tsx         список: регион, сортировка, счётчик, пустое состояние
│   ├── FiltersPage.tsx      фильтры со счётчиком результатов
│   ├── DetailPage.tsx       карточка объявления
│   ├── WizardPage.tsx       мастер публикации с черновиком
│   └── PublishedPage.tsx    экран после публикации
├── realty/  auto/  services/  home/  electronics/
├── personal/  hobby/  pets/  travel/  kids/
├── work/                    адаптер к готовому модулю features/work
└── index.ts                 список зарегистрированных категорий
```

## Как добавить категорию

1. Создать `categories/<id>/index.ts` с объектом `CategoryModule`.
2. Дописать одну строку `registerCategory(...)` в `categories/index.ts`.
3. Если категория должна быть на главной — добавить плитку в `core/homeGrid.ts`.

Больше ничего. Роутинг, список, фильтры, карточка и мастер появятся сами.

## Как подключить категорию со своим интерфейсом

Если типовые экраны не подходят (как для «Работы», где резюме и вакансии не
описываются полями объявления), категория объявляет `customRoutes`:

```ts
export const workCategory: CategoryModule = {
  id: 'work',
  title: 'Работа',
  icon: 'work',
  path: '/work',
  intents: [],
  subcategories: [],
  customRoutes: () => import('./WorkModuleEntry'),
};
```

Модуль грузится лениво: если его чанк не загрузится, остальные категории не
пострадают.

## Что закрыто из разбора макетов

- Регион известен **до** открытия списка и виден чипом над ним. Раньше он
  спрашивался только в фильтрах, и список открывался с перемешанными городами.
- Фильтры живут в URL, поэтому возврат из карточки их сохраняет.
- Авторизация вынесена в `AuthGate`: `requireAuth('publish' | 'contact' |
  'respond' | 'favorite')`. Экран сам не решает, авторизован ли пользователь.
  После входа человек возвращается ровно туда, откуда пришёл.
- Мастер публикации показывает «шаг N из M» и сохраняет черновик после каждого
  шага. Повреждённый черновик не роняет форму — она начинается с чистого листа.
- Пустые состояния: ничего не найдено по фильтрам, пустой раздел, объявление
  снято с публикации. У каждого есть действие, а не только текст.
- После публикации — «Мои объявления», а не главная.
- Сетка главного экрана описана один раз. Нереализованные категории видны с
  пометкой «скоро» вместо перехода в тупик.
- «Недвижимость»: кадастровый номер первым шагом (по нему подтягиваются
  площадь и ВРИ); ИЖС, СНТ и ЛПХ сведены в одно корректное поле «вид
  разрешённого использования» вместо путаницы с категорией земель.
- «Авто»: VIN первым шагом; тип топлива и объём двигателя разделены; привод и
  цвет стали фильтруемыми; число владельцев по ПТС выведено в карточку.

## Что осталось

- Бэкенд: `apps/api` — заглушки. Формат `CatalogItem` в `core/catalogData.ts`
  совпадает с ожидаемым ответом API, поэтому замена демоданных на реальные
  не потребует переделки экранов.
- Загрузка фотографий: поле `photos` пока текстовое, нужен файловый компонент.
- Поиск по всему сайту (`features/search`) не связан с реестром категорий.
- Верификация продавцов: поле `seller.verified` есть, процесса нет.
- Nova Bot — по решению продукта на финальный этап.

